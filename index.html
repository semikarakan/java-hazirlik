1 Kalıtım (Inheritance) & super Kuralları

extends

Alt sınıf (Subclass/Child), üst sınıfın (Superclass/Parent) public ve protected özelliklerini ve metotlarını miras alır. Kod tekrarını önler.

🔥 Kağıt Sınavı Tuzağı 1 (Constructor & super): Üst sınıfta parametreli bir constructor varsa (Örn: Karakter(int can, ...) veya Gonderi(String takipNo, double agirlik)) ve parametresiz constructor yoksa, alt sınıfın constructor'ında İLK SATIRDA super(...); çağrılmak ZORUNDADIR!
🔥 Kağıt Sınavı Tuzağı 2 (super.metot()): Alt sınıfta bir metodu @Override ettiğinde üst sınıftaki orijinal metodu da çalıştırmak istiyorsan super.kos(); veya super.bilgiGoster(); yazmalısın (Tavşan ve RPG Karakterlerinde olduğu gibi).

3 Soyutlama (Abstraction) Mantığı

Ne Yapar? vs Nasıl Yapar?

Bir sınıfın "ne yaptığını" dışarıya gösterip, "nasıl yaptığının" karmaşık detaylarını gizlemektir. Hocanın kodlarında 2 şekilde uygulanmıştır:

  • 1. Yardımcı Metotları private Yapmak:
    • Insan.java içinde private String musteriNoOlustur() (Dışarıdan kimse çağıramaz, sadece constructor içinde otomatik çalışır).
    • Karakter.java içinde private int savun() (Sadece saldir() metodu kendi içinde çağırır).
    • Sistem.java içinde private String rasgeleTakipNoOlustur().
  • 2. abstract class ve interface Kullanmak:
    Gonderi sınıfında public abstract double ucretHesapla(); tanımlanır; nasıl hesaplanacağına alt sınıflar (StandartKargo / HizliKargo) karar verir.

4 Çok-Biçimlilik (Polymorphism) & En Büyük Tuzak

ÇOK KRİTİK

Üst sınıf veya Arayüz (Interface) referansının, alt sınıf nesnelerini tutabilmesidir: 

Insan insan2 = new Musteri("Veli");
insan2.bilgiGoster();  // ✅ ÇALIŞIR (Insan sınıfında var, Musteri'nin noOlustur'unu kullanır)
// insan2.bakiyeGoster(); // ❌ DERLEME HATASI (Compile Error)!

// ÇÖZÜM (Downcasting / Tip Dönüşümü):
((Musteri) insan2).bakiyeGoster(); // ✅ ÇALIŞIR!
📌 Altın Kural: Bir referans üzerinden hangi metotların çağrılabileceğine derleme zamanında Referans Tipi (Sol Taraf - Insan) karar verir. Çağrılan metodun hangi versiyonunun çalışacağına ise çalışma zamanında Nesne Tipi (Sağ Taraf - new Musteri()) karar verir!

2. UML Sınıf Diyagramları (Class Diagrams) Görsel Rehberi

Kağıt üzerinde hem UML diyagramından Java koduna dönüştürme hem de verilen kodun UML diyagramını çizme sorularında dikkat etmen gereken tüm ok uçları, çizgi tipleri ve çokluk (multiplicity) kuralları.

📦 UML Sınıf Kutusunun 3 Bölmesi

UML Class diyagramlarında her sınıf 3 katmanlı bir dikdörtgen ile gösterilir. Java'da önce tip sonra isim yazılırken (String takipNo), UML'de önce erişim işareti, sonra isim, iki nokta üst üste (:) ve en son tip yazılır!

  • 1. Üst Bölme (Sınıf Adı): Soyut sınıf ise İtalik yazılır veya üstüne <<abstract>> konur. Arayüz ise <<interface>> yazılır.
  • 2. Orta Bölme (Attributes / Özellikler):
    Format: [+/-/#:~] degiskenAdi : veriTipi
    Örnek: # takipNo : String
  • 3. Alt Bölme (Methods / Metotlar):
    Format: [+/-/#:~] metotAdi(param : tip) : donusTipi
    Örnek: + ucretHesapla() : double
<<abstract>>
Gonderi
# takipNo : String
# agirlik : double
# sigortaDurumu : boolean
# teslimDurumu : boolean
# ucret : double
+ Gonderi(takipNo:String, agirlik:double)
+ ucretHesapla() : double
+ gonderiBilgisi() : void
<<interface>>
Sigortalanabilir
+ standartSigortaUcreti : double = 100
+ hizliSigortaUcreti : double = 500
+ sigotaIslemiYap() : void
💡 Interface içindeki özellikler otomatik public static final, metotlar public abstract kabul edilir.
1. Generalization / Inheritance (Kalıtım) "is-a" (bir ...-dır)

Alt sınıftan üst sınıfa doğru DÜZ ÇİZGİ ve İÇİ BOŞ ÜÇGEN OK çizilir. Kod karşılığı: extends.

public class Tortoise extends Animal
2. Realization / Implementation (Gerçekleşme) Arayüz Uygulama

Sınıftan arayüze (interface) doğru KESİKLİ ÇİZGİ ve İÇİ BOŞ ÜÇGEN OK çizilir. Kod karşılığı: implements.

public class Student implements Person
3. Aggregation (Zayıf Parça İlişkisi) İçi Boş Elmas ◇

Tekerlek (Wheel) arabanın (Car) bir parçasıdır. Ancak araba yok olduğunda tekerlek tek başına varlığını sürdürebilir! Elmas her zaman "Bütün" (Car) tarafındadır.

Bütün yok olsa da parça yaşar (Araba - Tekerlek)
4. Composition (Güçlü Parça İlişkisi) İçi Dolu Elmas ◆

Kalp (Heart) insanın (Human) bir parçasıdır. İnsan sınıfı yok olduğunda kalp de yok olacaktır! İçi dolu siyah elmas "Bütün" (Human) tarafına çizilir.

Bütün yok olursa parça da yok olur (İnsan - Kalp)

🔗 Association (Bağlantı / Sahiplik "has-a") ve Çokluk (Multiplicity) Göstergeleri

Gösterim Anlamı (Slayttaki İfade) Java Karşılığı
0..1 Sıfır ya da bir durum (Opsiyonel) Directory parent; (null olabilir)
1 veya 1..1 Tam olarak bir durum Address address;
0..* veya * Sıfır ya da daha fazla (sonsuz) ArrayList<Course> courses;
1..* Bir ya da daha fazla (en az 1) En az 1 elemanlı liste/dizi
1. Tek Yönlü Ok (Person ───lives at───> 1 Address):
Okunuşu: "İnsan bir adrese sahiptir." Person sınıfı içinde Address tipinde bir değişken vardır. (Eğer 1 yerine 0..* olsaydı ArrayList<Address> olurdu).
2. Reflexive (Dönüşlü) Association (Directory):
Sınıfın kendi kendisiyle yaptığı ilişkidir. Bir Directory (Dosya dizini) 0..* alt dizine (subdirectory) ve 0..1 üst dizine (parent) sahip olabilir.
